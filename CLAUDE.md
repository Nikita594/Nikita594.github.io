# Репозиторий nikita594.github.io

Сайт на GitHub Pages. В корне — старая учебная страница «Страны» (`index.html`, `css/`, `image/`), её не трогаем.

Основной проект — **«Ритм»**, планировщик задач и недели для одного пользователя (16 лет, Россия, MacBook + телефон).
Интерфейс только на русском, неделя с понедельника. Полностью бесплатно, без аккаунтов, без внешних сервисов и аналитики,
данные только на устройстве (IndexedDB).

- `ritm-app/` — исходники приложения.
- `ritm/` — готовая сборка, которую раздаёт GitHub Pages: https://nikita594.github.io/ritm/ (появляется после `npm run release`).
- `ritm-app/PLAN.md` — утверждённый план: схема данных, решения, порядок работ.
- Исходное задание — версии 1 и 2 (см. PLAN.md). Версию 2 начинать только после того, как пользователь проверит версию 1.
- Статус: версия 1 готова и выпущена в `ritm/` (ждёт проверки пользователем). После проверки 32 найденные ошибки исправлены; повторная проверка исправлений остановлена по просьбе пользователя — непроверенные находки ревьюера быстрого ввода см. в истории (например, «через 1,5 часа», «в 10 часов 30 минут», «каждый месяц 25 ноября»).

## Стек

React 19 + TypeScript 7 + Vite 8, Tailwind 4, Dexie 4 (IndexedDB), date-fns 4 (локаль ru), chrono-node (только `ru`, для дат в быстром вводе),
vite-plugin-pwa (service worker, манифест), vite-plugin-singlefile (однофайловая сборка), Vitest.
Recharts — добавить в версии 2 для графиков. Новых зависимостей без нужды не добавлять.

## Команды (из `ritm-app/`)

| Команда | Что делает |
|---|---|
| `npm run dev` | режим разработки |
| `npm test` | тесты логики (Vitest) |
| `npm run typecheck` | проверка типов |
| `npm run build` | PWA-сборка в `dist/` |
| `npm run build:single` | однофайловая сборка в `dist-single/index.html` |
| `npm run release` | обе сборки + копирование в `../ritm/` (`ritm/ritm-offline.html` — один файл) |
| `npm run check` | всё сразу: типы, тесты, обе сборки, e2e |
| `E2E_RELEASE=1 npm run e2e` | те же проверки, но по готовому выпуску в `../ritm/` |
| `npm run e2e` | проверки в Chromium: офлайн, file://, 375 px и т. д. Нужны собранные `dist/` и `dist-single/`. В облачной среде: `PLAYWRIGHT_PATH=/opt/node22/lib/node_modules/playwright npm run e2e` |

После каждого шага: `npm run check` (типы → тесты → обе сборки → e2e, останавливается на первой ошибке; в облаке с `PLAYWRIGHT_PATH=…`), затем отдельный коммит. Не коммитить, если `check` упал (не прятать код выхода за `| tail`).
Форматирование: `prettier --write "src/**/*.{ts,tsx,css}" "e2e/*.mjs"` (настройки в `.prettierrc`: без `;`, одинарные кавычки, ширина 140).

## Устройство кода

- `src/db/` — Dexie: `types.ts` (все типы записей), `db.ts` (схема и версии), `seed.ts` (первый запуск: «Входящие», 8 категорий), `settings.ts` (настройки key-value + значения по умолчанию).
- `src/domain/` — чистая логика без React, с тестами рядом (`*.test.ts`). Всё, что можно протестировать, — сюда.
- `src/features/<раздел>/` — экраны.
- `src/ui/` — общие компоненты (`kit.tsx`), иконки (свои SVG), `Screen`, тосты.
- `src/lib/` — hash-роутер (`#/today`, `#/list/<id>`…), service worker, тема.
- `e2e/` — сценарии Playwright (`scenarios.mjs`) и мини-сервер, раздающий `dist/` по пути `/ritm/`.

## Принятые решения

- Даты хранятся строками `ГГГГ-ММ-ДД` по местному времени, время дня — минутами от полуночи, моменты — миллисекундами. Это убирает ошибки часовых поясов.
- id — случайные строки (`src/lib/id.ts`, через `crypto.getRandomValues`: `randomUUID` недоступен в некоторых контекстах file://).
- Встроенные категории имеют постоянные id (`study`, `english`, `sat`, `work`, `channel`, `sport`, `games`, `rest`).
- Список «Входящие» — обычный список с id `inbox`, удалить нельзя.
- Схема версионируется: старые `db.version(n)` не менять, добавлять новую версию с `upgrade`; для старых резервных копий — шаг миграции данных экспорта.
- Таблицы версии 2 (цели, копилка, разборы) созданы сразу в версии схемы 1.
- `base: './'` — сборка работает в любой подпапке и с file://.
- Однофайловая сборка: `__SINGLE_FILE__ = true`, service worker не регистрируется. В Chromium IndexedDB на file:// работает и переживает перезапуск; Safari с file:// не проверен — советуем Chrome/Яндекс Браузер.
- Service worker регистрируем сами (`src/lib/sw.ts`), `registerType: autoUpdate`; при обновлении показываем тост «Перезагрузить».
- Базовые стили — в `@layer base`, иначе они перебивают утилиты Tailwind 4.
- Тема: класс `.dark` на `<html>`, цвета — CSS-переменные (`bg-surface`, `text-muted`, `bg-accent`…), выбор дублируется в localStorage, чтобы не мигало при загрузке.
- Быстрый ввод (`src/domain/quickAdd.ts`): сначала свои токены (`!N`, `#категория`, `~список`, длительность), потом `rewrite()` приводит «к пятнице», «до среды», «вс», «20.10», «2 часа дня» к формам, которые понимает chrono, затем chrono (`chrono-node/ru`, `forwardDate`). Поправки: «в 7» без «утра/вечера» и без минут = 19:00; только время → сегодня, а если прошло — завтра; день недели, совпадающий с сегодняшним, → через неделю; одиночные «неделя», «месяц» и т. п. — не дата. В JS `\b` не работает с кириллицей — границы слов через `(?<![\p{L}\p{N}])`. Неизвестная `#категория` остаётся в названии и подсвечивается.
- Повторы (`src/domain/repeat.ts`): при выполнении создаётся выполненная копия (`repeatOf` = id серии, без `repeat`), а сама задача получает следующий срок, подзадачи сбрасываются. Выполнил раньше — следующий повтор после срока; с опозданием — первый повтор строго после сегодняшнего дня (без «долгов»). «31-е» в коротком месяце — последний день. Повторяющаяся задача всегда со сроком.
- Календарь (`src/features/calendar/`): 48 px на час, сетка 15 минут, геометрия — в `src/domain/calendar.ts`. Мышь: протянуть по пустому месту — новый блок, клик — блок на час; блок тянется целиком, нижний край — длина. Палец: пустое место прокручивается, нажатие создаёт блок, двигать — за ручку ⠿, длина — за нижний край (`touch-none`). Тип последнего нажатия запоминаем сами (в Safari у `click` нет `pointerType`). Задача из панели: мышью тянуть, либо нажать на задачу и потом на время; при постановке задача получает срок и время начала. На телефоне — один день с полоской дней.
- Помодоро (`src/domain/pomodoro.ts` — чистая логика, `src/features/timer/`): состояние в настройках (ключ `pomodoro`), время по `Date.now()`, а не по тикам. `PomodoroRunner` в App ставит `setTimeout` на конец фазы и в одной транзакции пишет запись `entries` (source `timer`) — защита от двойной записи из двух вкладок. Запись = чистое время фокуса без пауз, заканчивается в момент окончания фазы (даже если приложение было закрыто). «Стоп» записывает, если набежало ≥ 1 минуты. Звук — Web Audio, «разблокируется» по кнопке «Старт». В e2e время перематывается `page.clock`.
- Привычки (`src/domain/habits.ts`): `days: []` — каждый день. Серия считает только дни по расписанию; неотмеченное «сегодня» серию не рвёт; отсчёт — с даты создания или самой ранней отметки (можно отмечать задним числом). На «Сегодня» — блок привычек на этот день.
- Горячие клавиши (`src/lib/hotkeys.ts`, `src/app/Shortcuts.tsx`): по `event.code`, поэтому работают на русской раскладке; одиночные клавиши не срабатывают в полях ввода и при открытом окне; ⌘/Ctrl+K — всегда. Справка — `SHORTCUTS` (окно «?» и настройки).
- Тема: `App` читает настройку `theme` с начальным значением `null` и не трогает `<html>`, пока она не загружена — иначе на миг применялась тема по умолчанию (мигание).
- Резервная копия (`src/db/backup.ts`, `src/features/backup/`): JSON `{app, schemaVersion, exportedAt, tables}`; служебные настройки устройства (`pomodoro`, `lastBackupAt`, `backupSnoozedUntil`, `installedAt`) в копию не попадают и при восстановлении не перезаписываются. Восстановление заменяет все данные в одной транзакции. На телефоне сохранение — через «Поделиться», на компьютере — скачивание. Напоминание — если 7 дней с последней копии или с первого запуска (`installedAt` пишется в seed), «Позже» — на 3 дня. e2e сравнивает все таблицы устройства А с чистым устройством Б и с однофайловой версией.
- Быстрый ввод при сохранении разбирает строку заново по свежим данным из базы и очищает поле сразу.
- Приоритеты: 0 нет, 1 низкий, 2 средний, 3 высокий. В быстром вводе `!1` — высокий, `!2` — средний, `!3` — низкий.
- Копилка (версия 2): суммы в копейках/центах, показывать и в ₽, и в $; курс задаётся в настройках (`usdRateKopecks`).
- Редкие экраны (Неделя, Таймер, Привычки, Матрица, Настройки, Поиск, Выполнено) — `React.lazy` в `App.tsx`; service worker кэширует все части, в однофайловой версии они встроены. В e2e после перехода на такой экран ждать его элемент, а не сразу обращаться к DOM.
- `main.tsx` сначала открывает базу и только потом рисует приложение; если IndexedDB недоступна — `FallbackScreen` с объяснением, ошибки отрисовки ловит `ErrorBoundary`.
- Поля даты/времени/чисел, связанные с базой, — только через `DraftInput` (`ui/kit.tsx`), иначе ввод по цифрам в Chrome ломается.
- Бледный текст (`--c-faint`) не ниже 4.5:1 к фону в обеих темах (Lighthouse: доступность 100).
- В корне сайта лежит `.nojekyll`: GitHub Pages не прячет файлы, начинающиеся с «_».
- Выпуск: `npm run release` → закоммитить папку `ritm/`. Сайт обновляется после попадания в `main`.
- `npm audit` ругается на `braces` внутри vite-plugin-singlefile — это инструмент сборки, в приложение не попадает.
- Lighthouse больше не проверяет PWA; устанавливаемость проверяем по манифесту, иконкам и service worker (e2e).

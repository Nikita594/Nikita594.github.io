# «Ритм» — план до начала работы

## 1. Что уже проверено

| Вопрос | Результат |
|---|---|
| Есть ли готовый разборщик русских дат | Да: `chrono-node` 2.10.3, локаль `ru`. Проверил фразы «завтра в 18:00», «сегодня», «послезавтра», «в пятницу в 7 вечера», «через 3 дня», «в понедельник в 9:30», «15 октября», «в субботу в 19» — все разобраны верно. Длительность («1ч»), приоритет («!2»), категорию («#учёба») он не понимает — это допишу сам, с тестами. |
| Работает ли хранилище при открытии файла двойным кликом | В Chromium (Chrome, Яндекс Браузер, Edge) — да, данные переживают перезапуск браузера. В Safari с `file://` проверить здесь не могу — для однофайловой версии на Mac советую Chrome или Яндекс Браузер. |
| Lighthouse и PWA | В новых версиях Lighthouse раздела «PWA» больше нет. Устанавливаемость проверю по критериям Chrome: манифест, иконки, service worker, https. |
| Актуальные версии | React 19.3, TypeScript 7.0, Vite 8.3, Tailwind 4.3, Dexie 4.4, date-fns 4.4, Recharts 3.10, vite-plugin-pwa 2.0, vite-plugin-singlefile 2.3, Vitest 5.0 — совместимы между собой. |

## 2. Где будет жить приложение

- `ritm-app/` — исходный код.
- `ritm/` — готовая сборка. После слияния ветки в `main` приложение откроется по адресу **https://nikita594.github.io/ritm/**. Страница «Страны» в корне сайта остаётся как есть.
- `ritm/ritm-offline.html` — однофайловая версия: её можно скачать и открывать двойным кликом.
- Синхронизации между Mac и телефоном нет: данные хранятся только на устройстве. Перенос — файлом резервной копии (AirDrop, Telegram «Избранное» и т. п.).

## 4. Схема данных

Обозначения: `Дата` — строка `ГГГГ-ММ-ДД` по местному времени; `Мин` — минуты от начала суток (18:00 = 1080); `Момент` — точное время в миллисекундах.

```ts
Задача (tasks) {
  id, title, note
  listId                       // 'inbox' = «Входящие»
  priority: 0 | 1 | 2 | 3      // нет / низкий / средний / высокий
  dueDate?: Дата, dueTime?: Мин   // время необязательно
  durationMin?: число
  subtasks: { id, title, done }[]
  repeat?: Повтор
  categoryId?
  goalId?                      // связь с целью (версия 2)
  pinnedWeek?: Дата            // «главное на неделю» из разбора (версия 2)
  status: 'open' | 'done'
  completedAt?: Момент
  repeatOf?: id                // запись о выполненном повторе
  order, createdAt, updatedAt
}
Повтор = каждый день | по будням | по дням недели [пн..вс] | раз в N дней | раз в месяц (число) ; + необязательная дата окончания

Список (lists)          { id, name, color, order }
Категория (categories)  { id, name, color, builtin, weeklyLimitMin?, archived, order }
                        // встроенные: учёба, английский, SAT, работа, канал, спорт, игры, отдых
Блок времени (blocks)   { id, date: Дата, startMin, endMin, categoryId?, taskId?, title? }
Факт времени (entries)  { id, categoryId?, taskId?, start: Момент, end: Момент,
                          source: 'timer' | 'manual', unplanned?, before? }  // before — «что было перед этим» (v2)
Привычка (habits)       { id, name, color, days: [1..7], archived, order }
Отметка (habitChecks)   { id = привычка+дата, habitId, date: Дата }
Цель (goals)            { id, title, level: 'main' | 'season' | 'week', parentId?,
                          from?: Дата, to?: Дата, status, note }
                        // прогресс = выполненные связанные задачи / все связанные
Копилка (savings)       { id, title, target }                       // сумма в копейках
Деньги (money)          { id, date, kind: 'income' | 'expense' | 'save', amount, note, savingsId? }
Разбор недели (reviews) { id = понедельник недели, answers: { good, hindered, focus },
                          snapshot: сводка, focusTaskId }
Настройки (settings)    { key, value }   // тема, лимит часов в день, сон, помодоро, дата последней копии
```

- Таблицы версии 2 создаются сразу, чтобы потом не переделывать базу.
- База версионируется с первого дня: каждое изменение структуры — новая версия с шагом миграции. Резервная копия хранит номер версии, поэтому старые копии тоже восстанавливаются.

## 5. Как будет работать (решения по умолчанию)

- **Быстрый ввод:** `английский завтра в 18:00 1ч !2 #учёба` → задача «английский», завтра 18:00, 1 час, средний приоритет, категория «учёба». `!1` — высокий, `!2` — средний, `!3` — низкий. `~список` кладёт задачу в список. Под полем ввода видно, что распознано, ещё до сохранения.
- **Повтор:** выполненная задача остаётся в истории («Выполнено», статистика) и переезжает на следующую дату. После пропущенных дней следующая дата — сегодня или позже, без цепочки «долгов».
- **Виды:** «Сегодня» (прошлые несделанные — в свёрнутом блоке, без счётчика), «Следующие 7 дней» по дням, «Входящие», «Выполнено» по дням выполнения, поиск.
- **Неделя:** сетка пн–вс, шаг 15 минут, часы 6:00–24:00 (меняется в настройках). Перетаскивание по пустому месту создаёт блок, блок можно двигать, нижний край меняет длину, задачу из боковой панели можно перетащить в слот. На телефоне — один день с переключением.
- **Помодоро:** 25/5, длинный перерыв 15 после 4 подходов (меняется). Таймер считает по часам, а не по тикам, поэтому не сбивается в фоне и переживает перезагрузку. Время фокуса пишется в «факт». Факт можно добавить и вручную.
- **Привычки:** каждый день или по выбранным дням; сетка дней; текущая и лучшая серия. Дни вне расписания серию не прерывают, неотмеченное «сегодня» — тоже, пока день не кончился.
- **Матрица:** важно = высокий или средний приоритет; срочно = срок до конца завтрашнего дня или уже прошёл.
- **Клавиши** (работают и на русской раскладке): `N` — новая задача, `/` — поиск, `T` — Сегодня, `W` — Неделя, `P` — таймер, `?` — список клавиш, `Esc` — закрыть.
- **Резервная копия:** один JSON-файл со всеми данными. Импорт показывает, что внутри, и после подтверждения заменяет данные. Если копии не было 7 дней — тихая строка внизу экрана с кнопками «Сохранить» и «Позже».
- Приложение просит браузер не удалять данные (`navigator.storage.persist`). Safari на iPhone может стереть данные сайта, который не открывали неделю; у приложения, добавленного на экран «Домой», свой счётчик. Поэтому напоминание о копии важно.

```

    lib/         навигация, горячие клавиши, тема
  e2e/           проверки в настоящем браузере: офлайн, перезагрузка, file://, 375 px
  README.md
ritm/            готовая сборка для сайта
CLAUDE.md        описание проекта для следующих сессий
```

## 7. Порядок работ

Каждый шаг — рабочее приложение, зелёные тесты, отдельный коммит.

0. Каркас: сборка, база, PWA, однофайловая версия, тесты, CLAUDE.md, README.
1. Списки и задачи: подзадачи, приоритеты, перенос, поиск.
2. Быстрый ввод + тесты разбора.
3. Повторы + тесты.
4. Виды «Сегодня», «7 дней», «Входящие», «Выполнено».
5. Неделя-календарь с перетаскиванием.
6. Помодоро и ручной ввод факта.
7. Привычки и серии.
8. Матрица Эйзенхауэра.
9. Темы и горячие клавиши.
10. Экспорт, импорт, напоминание о копии.
11. Сборка в `ritm/` и проверка пунктов «Готово, когда».

**Пауза: вы проверяете версию 1.** Версия 2 — только после этого.
